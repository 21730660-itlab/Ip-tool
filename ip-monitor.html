Database file

the app's data, kept in its own file

The app and the data are two separate files: IP-Monitor.html is the program, ip-monitor-db.json is the database. Link the database once and every change is written to it straight away. Keep both files together, copy the .json to back it up, and open the same .json from another computer to see the same data.

Restore points

automatic dated backups

A copy of all data is saved every day, and before every restore, template or bulk import. The newest 30 are kept. Press Restore to go back to one.

Live status (ping)

which devices answer

A web page can't ping by itself, so a small helper does it on a Windows PC: put ip-monitor-ping-helper.cmd in the same folder as ip-monitor-db.json and double-click it. Every minute it pings each device's IP and writes ip-monitor-status.json. Link that file here once; the dashboard, device list, map and health check then show who is online.

Backup

JSON · CSV

Every export is organized as Site → Network → Host, numbered 1, 1.1, 1.1.1 so each row shows exactly where it belongs.

One file with the whole app and all data inside. Give it to someone and they open it with the same sites, networks, hosts and accounts.

Export by device type

one file per type · CSV

Each button saves only that kind of device, for example IP cameras alone or servers alone.

To keep the online app and the offline copy the same: export a backup (.json) from one and import it into the other. Newer changes win, and accounts come along when an administrator exports.
